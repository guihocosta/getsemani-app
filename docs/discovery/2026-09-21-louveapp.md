# Discovery — LouveApp (foco: louvor)

**Data:** 21/09/2026
**Fonte:** navegação logada em https://app.louveapp.com.br (ministério de teste, dados vazios)
**Objetivo:** mapear funcionalidades de um concorrente maduro para alimentar o backlog do Getsemani-App.

## 2. Repertório (módulo inexistente no Getsemani)

- **Música**: título, artista, observações gerais (0/150).
- **Versões por música** (ex.: "Original", acústica, ao vivo). Cada versão tem:
  - Nome da versão (0/20)
  - Classificações (ex.: Louvor) — taxonomia configurável no ministério
  - Observações
  - **Tom** e **BPM**
  - Duração (h:m:s)
  - Referências: link letra, link cifra, link áudio, link vídeo, "adicionar referência", arquivo customizado
  - Botão **Autopreenchimento** das referências
  - Ação **Clonar** versão
- **Cadastro assistido**: busca integrada ao **Deezer** por título/artista; cards de sugestão ("Bondade de Deus", "Jeová Jireh") com "Adicionar ao repertório".
- **Cadastrar manualmente** e **Importar músicas** (lote).
- Organização em **Pastas** e por **Artistas**.

## 3. Escala (criação)

Abas: **Detalhes | Participantes | Músicas | Roteiro**.

**Detalhes**
- Título, Data, Hora
- **Repetir** (recorrência)
- Observações (0/500)
- **Publicar escala** — visível para todos os membros (toggle → permite rascunho)
- **Pedir confirmação** — participantes confirmam presença (toggle)
- Paleta de cores
- Roteiro (atalho, contador de itens)

**Participantes**
- Adicionar avulso · **Equipes** (bloco de pessoas pré-montado) · **Preencher auto**

**Músicas**
- Adicionar · **Preencher auto**

**Roteiro**
- Adicionar **Evento** · **Modelos** (templates salvos no ministério)
- "As músicas do roteiro são adicionadas automaticamente com base na seleção feita na aba 'Músicas'."

**Criação alternativa**: além de "Nova escala (manual)", existe **"Gerar escala automática — sugerir membros e músicas com base no histórico"**.

## 4. Panorama de escalas

Grade **função × datas do mês** (linhas: Ministro, Vocalista, Backing vocal, Violão, Guitarra…). Modo "Compacta". Painel de filtros: mês, faixa de horas (0h/24h), membros, dias da semana (toggle por dia).

## 5. Visão geral (dashboard)

Cards com filtro de período (7 dias / 1 mês / mês atual / 3 meses / intervalo custom), dias da semana, faixa de horas, membros:

- Escalas
- Músicas selecionadas
- Membros escalados (x/y + %)
- Total de escalações
- **Confirmações de presença** (%)
- **Faltas** (%)
- Indisponibilidades
- Funções associadas

## 6. Ministério / administração

- **Equipes** (agrupamento de membros para escalar em bloco)
- **Funções** (com ícone/emoji por função)
- **Classificações** (taxonomia de músicas)
- **Administradores**
- **Módulos** — liga/desliga o módulo Repertório por ministério. Desligado, some: aba de repertório, músicas nas escalas, relatórios de músicas, metrônomo, classificações. Pensado para ministérios sem música (multimídia, transmissão, iluminação, projeção).
- **Modelos de roteiro**
- **Lixeira** (soft delete)
- **Integrações**: Holyrics (projeção), Tokens de API

## 8. Observações de custo (relevante para a constituição "custo zero")

- Busca de músicas depende de **API Deezer** (externa).
- "Gerar escala automática" e "Preencher auto" são heurísticas sobre histórico — não exigem IA paga.
- "Autopreenchimento" de referências implica scraping/API de terceiros.
- Chat em tempo real exige infraestrutura de realtime.
- Integração Holyrics roda na rede local da igreja.

---

## 9. Triagem: o que cabe no Getsemani (custo zero + YAGNI)

### Entra — custo zero, alto valor

| Funcionalidade | Por quê | Custo |
|---|---|---|
| **Confirmação de presença** na alocação | Resolve a dor real ("o escalado viu? vai?"). Encaixa direto em `Allocation` (status + timestamp). Push já existe. | 1 coluna + 1 action |
| **Faltas / histórico de presença** | Consequência da anterior; dá base para relatórios e para o rodízio. | derivado |
| **Rascunho vs publicada** na escala | Líder monta com calma e publica quando fecha. Evita notificar escala errada. | 1 booleano + gate |
| **Repertório: música + versões (tom, BPM, duração, links)** | Núcleo do louvor. Tudo é texto e URL digitados pelo líder — zero API. Links apontam para Letras/Cifra Club/YouTube/Spotify já existentes. | 2 tabelas |
| **Músicas na escala** | Liga repertório ↔ escala; é o que o músico abre no domingo. | tabela de junção |
| **Roteiro do culto + modelos de roteiro** | Serve a igreja inteira (não só louvor): ordem do culto, quem faz o quê, horários. Modelo reutilizável mata o trabalho repetido. | 2 tabelas |
| **Panorama (grade função × data)** | Só uma view dos dados que já temos. Enxergar buracos na escala em 1 tela. | 1 página |
| **Dashboard de métricas** | Agregações Prisma sobre dados existentes. | 1 página |
| **Equipes** (escalar bloco de pessoas) | Banda que sempre toca junta vira 1 clique. | 1 tabela |
| **Classificações de música** | Taxonomia pequena (Louvor/Adoração/Ceia/Entrada) que torna o repertório útil. | enum/tabela |
| **Avisos / mural do ministério** | Substitui recado perdido no WhatsApp. Push já existe. | 1 tabela |
| **Aniversariantes** | Campo de data no `User` + listagem. Cuidado pastoral barato. | trivial |
| **Metrônomo + Tap BPM** | 100% client-side (Web Audio API). Nenhum backend. | 1 componente |
| **Módulos liga/desliga por ministério** | Já é a arquitetura modular da constituição. Repertório só aparece para quem toca. | flag |
| **Lixeira / soft delete** | Erro de líder não vira perda de dados. | coluna `deletedAt` |

### Entra com ressalva

| Funcionalidade | Ressalva |
|---|---|
| **Sugestão automática de escalação** | Fazer como *heurística determinística* (rodízio por menor nº de escalações + respeita indisponibilidade + capacitação), **nunca** IA paga. Já temos rodízio implementado — é evoluir, não criar. |
| **Preencher músicas auto** | Só se for "as N menos tocadas nos últimos X cultos". Regra simples, sem histórico externo. |
| **Paleta de cores na escala** | Cosmético. Só se sobrar tempo. |

### Fica de fora

| Funcionalidade | Motivo |
|---|---|
| **Busca Deezer / autopreenchimento de referências** | Depende de API externa e chave. Viola custo zero e adiciona ponto de falha. Substituto: o líder cola o link (leva 10s) e nós validamos o formato. |
| **"Mais tocadas no LouveApp"** | Exige base multi-igreja. Não temos e não queremos. |
| **Chat em tempo real** | A igreja já usa WhatsApp. Realtime custa infra e atenção. Avisos + push cobrem o necessário. |
| **Integração Holyrics** | Depende de máquina na rede local da igreja e protocolo próprio. Fora do escopo web. |
| **Tokens de API pública** | Não há consumidor. YAGNI puro. |
| **Planos / cobrança** | O app é interno da igreja. Não existe monetização. |
| **Importar músicas em lote** | Só faz sentido para quem migra de outro sistema. Se surgir, um script pontual resolve. |

### Ordem sugerida

1. Confirmação de presença + faltas
2. Rascunho/publicar escala
3. Módulo Repertório (música + versões + links) e músicas na escala
4. Roteiro do culto + modelos
5. Panorama (grade função × data)
6. Avisos, aniversariantes, metrônomo (baratos, podem entrar a qualquer momento)
7. Equipes, dashboard, lixeira
