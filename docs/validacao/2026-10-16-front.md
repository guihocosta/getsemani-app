## Alta

### F-01 — Waterfall na home (`async-parallel`)
`app/(app)/page.tsx:25-35`: a sequência é `requireUser` → `membership.findFirst` → `isLeaderOfAny` → `visibleMinistryIds`, e só depois o `Promise.all`. As três últimas dependem apenas de `user`.

```ts
const user = await requireUser();
const [activeMembership, isLeader, memberIds] = await Promise.all([
  prisma.membership.findFirst({ where: { userId: user.id, status: "ACTIVE" } }),
  isLeaderOfAny(user.id),
  visibleMinistryIds(user.id, user.isAdmin),
]);
if (!activeMembership) redirect("/onboarding");
```
Economiza 2 round-trips ao pooler na tela mais acessada. Alternativa: `memberIds.length === 0` já indica falta de membership ativa (`visibleMinistryIds` filtra `ACTIVE`, exceto para admin), e aí dá para eliminar a query extra.

## Médias

### F-02 — Pendências contadas 2× (`server-cache-react`)
`app/(app)/layout.tsx:14-20` e `app/(app)/page.tsx:43-50` rodam a mesma `ledMinistryIds` + `membership.count`. O layout também encadeia `isLeaderOfAny` → `ledMinistryIds` → `count` em série. **Correção:** extrair `pendingMembershipCount(user)` envolto em `cache()` em identity. Isso também ajuda o C-02 de acoplamento.

### F-03 — `/login` pesado (`bundle-conditional`)
Build: `/login` tem 65.5 kB de rota (207 kB first load), contra 103-167 kB das demais. `LoginForm.tsx:3` importa `createSupabaseBrowser` estaticamente, mas só usa no clique do Google.
```ts
async function signInGoogle() {
  const { createSupabaseBrowser } = await import("@/lib/supabase/client");
  ...
}
```
O `origin` em `LoginForm.tsx:7` também pode ser lido dentro do handler. É a primeira tela de quem instala o PWA.

### F-04 — `framer-motion` em todo `Button` (`bundle-*`)
`src/ui/Button.tsx:3,24`: `motion.button` só para hover/tap scale. O mesmo efeito sai em CSS (`transition-transform hover:scale-[1.01] active:scale-[0.98]`). Manter motion só em `BottomSheet`/`ConfirmDialog`/`SwipeNav`, onde há animação de entrada e gesto de verdade. Como motion também está no `AppShell`, o ganho aparece sobretudo no `/login`.

### F-05 — Labels sem associação (WCAG 1.3.1 / 4.1.2)
Padrão `<label>Texto</label><input/>` como irmãos, sem `htmlFor`/`id`. Leitor de tela anuncia "campo de edição" sem nome, e tocar no rótulo não foca o campo.
- `app/(app)/avisos/AnnouncementBoard.tsx:83,96,100`
- `app/(app)/repertorio/SongList.tsx:72,85,89,93`
- `app/(app)/repertorio/[id]/SongDetail.tsx:146,158,170,193,197,201,205`
- `app/(app)/admin/ministerios/EditMinistryForm.tsx:47,51,56`

**Correção:** envolver o campo no `<label>` (padrão já usado em `UnavailabilityForm.tsx`) ou usar `useId()` + `htmlFor`.

### F-06 — Setas do calendário
`app/(app)/escalas/EscalaCalendar.tsx:160-168`: botões só com ícone, sem `aria-label`, e área de toque ≈ 20 px (mínimo recomendado: 44 px). **Correção:** `aria-label="Mês anterior"` / `"Próximo mês"` + `min-h-11 min-w-11`.
